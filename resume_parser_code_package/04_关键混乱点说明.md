# 关键混乱点说明

## 1. 后端输出了两种字段

当前后端同时输出：

- 老字段
  - `experience`
  - `projects`
  - `education`

- 新字段
  - `experiences`
  - `projects_structured`
  - `educations`

老字段是字符串数组，新字段是对象数组。

这就导致前端很容易：
- 一会儿按字符串渲染
- 一会儿按对象渲染
- 一会儿又把两边 merge

## 2. 前端有自己的 parser

前端文件里并不是“只渲染”，而是还在自己做：

- 标题推断
- 时间提取
- bullet 拆分
- section 切分

这意味着：

后端已经解析过一遍，前端又再猜一遍。

## 3. `enrichProfile()` 是当前最容易串味的地方

这个函数会：

- 拿后端返回的数据
- 再拿本地 `parseResumeText()` 的结果
- 最后重新拼装成渲染用 profile

优点是兜底强。  
缺点是只要其中一边脏，最后页面就会混。

## 4. 真正应该保留的最终 schema

建议最后只保留：

```json
{
  "name": "string",
  "headline": "string",
  "email": "string",
  "phone": "string",
  "summary": ["string"],
  "tags": ["string"],
  "experiences": [
    {
      "date": "string",
      "title": "string",
      "descriptions": ["string"]
    }
  ],
  "projects": [
    {
      "date": "string",
      "title": "string",
      "descriptions": ["string"]
    }
  ],
  "educations": [
    {
      "date": "string",
      "title": "string",
      "descriptions": ["string"]
    }
  ]
}
```

## 5. 最后的正确分工

- 后端：只负责 parse
- 前端：只负责 render
- 不要前端再猜标题
- 不要再维护老字段
