# OfferGlow 简历解析代码包

这个文件夹是把当前“粘贴简历 -> 生成网页分身”相关代码，按职责拆开后整理出来的版本，方便你单独审。

## 文件结构

### 1. `01_backend_简历解析器.py`
- 来源：`local_ai_server.py`
- 作用：后端解析主链路
- 包含内容：
  - 文本清洗
  - 分区识别
  - 姓名 / 求职意向 / 联系方式提取
  - 经历 / 项目 / 教育的结构化拆分
  - 技能标签提取
  - DeepSeek 的 JSON Prompt

### 2. `02_frontend_本地兜底解析.js`
- 来源：`index.html`
- 作用：当前前端的 fallback parser
- 包含内容：
  - 当后端 / AI 解析不稳定时，前端自己再拆一次简历
  - 本地标题推断
  - 本地 bullets 拆分
  - 本地 tags 清洗
  - 把 API 结果和本地结果 merge

### 3. `03_frontend_网页分身渲染器.js`
- 来源：`index.html`
- 作用：把解析结果渲染成新打开的网页分身页面
- 包含内容：
  - 经验卡片
  - 项目卡片
  - 教育背景
  - 联系方式
  - 点击按钮后打开新页面的逻辑

## 现在这套代码为什么会乱

不是单点 bug，而是结构上有 3 个根因：

1. 后端和前端各自维护了一套 parser
2. 同时维护“老字段”和“新字段”两种数据结构
3. 前端又把后端结果和本地 fallback 结果 merge 了一次

所以你会看到这些常见问题：
- 标题重复
- 日期混进标题
- 描述丢失或被重复渲染
- 标签脏词太多
- 同一份内容在不同层被猜测和重组

## 你如果要先看重点，建议顺序

1. 先看 `01_backend_简历解析器.py`
2. 再看 `02_frontend_本地兜底解析.js`
3. 最后看 `03_frontend_网页分身渲染器.js`

## 我对这套代码的结论

当前最大问题不是“某个正则不准”，而是：

`解析职责没有收口，渲染又在继续猜数据。`

真正该做的是：

- 后端只输出一套稳定 schema
- 前端只渲染，不再二次解析和猜标题
